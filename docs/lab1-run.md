# Лабораторная 1: AI-ассистент студента

## Запуск на Mac

Откройте Docker Desktop и Ollama. Скачайте модель: `ollama pull qwen2.5:1.5b`.
В `.env` должны быть BOT_TOKEN, POSTGRES_PASSWORD и настройки модели:

```dotenv
LLM_BASE_URL=http://host.docker.internal:11434/v1
LLM_API_KEY=ollama
LLM_MODEL=qwen2.5:1.5b
LLM_TIMEOUT=120
LLM_MAX_TOKENS=700
HISTORY_MAX_MESSAGES=12
CONTEXT_MAX_CHARS=12000
```

Значение `ollama` — техническое значение, локальный сервер его игнорирует.
Для внешнего провайдера задайте его URL, модель и настоящий API-ключ.
Не запускайте два polling-процесса с одним Telegram-токеном.

```bash
docker compose --profile cloud up -d --build
docker compose --profile cloud ps
```

Профиль cloud включает бот в Compose; эта команда запускает его локально.
Бот по умолчанию работает в /study. Команды /translate и /quiz переключают
режим с удалением истории пользователя. /settings 0.7 меняет temperature;
/settings показывает настройки, /reset очищает историю без смены настроек.
Групповые и нетекстовые сообщения не обрабатываются.

## Архитектура

Telegram → handlers/student.py → assistant.py → history.py (PostgreSQL)
→ llm.py (Chat Completions) → разбиение ответа → Telegram.
Промпты: prompts.py. Конфигурация: config.py, переменные окружения.
Исходный echo-модуль сохранён для тестов шаблона, но в приложение не подключён.

## Контекст

Роли system/user/assistant передаются отдельно. История — целые пары
«вопрос — успешный ответ». База хранит последние 12 сообщений пользователя,
а запрос содержит максимум 12 сообщений, включая system и текущий вопрос.
Из-за сохранения целых пар в запрос войдёт до 10 исторических сообщений.
Ограничение объёма: 12000 символов суммарного содержимого входных сообщений.
Это приближённая оценка объёма, а не точный подсчёт токенов.
Лимит символов не гарантирует попадание в окно любого провайдера: особенно
для кириллицы нужно согласовать его с фактическим контекстным окном сервера. В ответе максимум
700 токенов. Удаляются самые старые пары; system и текущий вопрос сохраняются.
Если один текущий вопрос с инструкцией превышает лимит, API не вызывается.
При ошибке модели пара не сохраняется. История и настройки восстанавливаются
из PostgreSQL после перезапуска; /reset затрагивает только вызвавшего пользователя.

Один пользователь обрабатывается последовательно, включая команды. Блокировки
действуют внутри одного процесса: текущая реализация рассчитана на один экземпляр
бота. Неполный ответ модели отклоняется и не сохраняется. Повторов API нет.
Маленькая модель может ошибаться в примерах кода и не соблюдать формат.

## Проверки

```bash
.venv/bin/python -m pytest -q
.venv/bin/ruff check app tests/test_lab1.py tests/test_compose.py
```

Тесты лабораторной используют подменённую модель и локальный тестовый HTTP-сервер,
не обращаются к Telegram или реальной LLM. Дополнительно требуется демонстрация
PostgreSQL двумя Telegram-пользователями до и после перезапуска:

1. Пользователь A: /study, /settings 0.0, затем «Запомни: мой проект называется Альфа».
2. Пользователь B: /quiz, /settings 1.0; проверить отсутствие знаний о проекте A.
3. Перезапустить контейнер `docker compose --profile cloud restart bot`.
4. A: /settings и вопрос о названии проекта. B: /settings.
5. A: /reset. Проверить сохранение настроек A и истории B.
6. A: сменить режим и проверить сброс истории. Проверить, что команды не уходят в LLM.

## Эксперимент и отчёт

Для каждого temperature 0.0, 0.3, 0.7, 1.0 сделать три запуска через Telegram.
Перед каждым: /study, /settings <значение>, /reset, одинаковый запрос.
Предлагаемый запрос: «Объясни разницу между списком и кортежем в Python
студенту первого курса. Покажи короткий пример и задай вопрос для самопроверки».
Зафиксировать точный системный промпт /study из prompts.py, дату, модель,
версию Ollama, лимит 700 токенов, прочие настройки. Оценивать три заголовка,
полноту, понятность, правильность примера. Сохранять все 12 ответов,
длину, наблюдения и доступные сведения о токенах. Telegram не показывает usage. Метод LLMClient.complete_result возвращает
текст и доступные счётчики токенов; scripts/experiment.py сохраняет их в JSON.
Сравнение неполного и улучшенного промпта проводится на одинаковом запросе,
с одним temperature и без истории; результаты нельзя подменять вымышленными.

Эксперимент через Telegram выполнен студентом: все 12 текстов и наблюдения
внесены в [отчёт](lab1-report.md) и [данные Telegram-запусков](lab1-experiment.json).
[Исходная копия ответов](lab1-telegram-source.txt) сохранена отдельно;
[CSV-таблица](lab1-experiment.csv) содержит длины и оценки формата.
Счётчики токенов этих Telegram-запусков не предоставлены.
[Программный эксперимент](lab1-api-experiment.json) сохранён как отдельный архив
с фактическим usage и сравнением двух инструкций.
